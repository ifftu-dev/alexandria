# Documentation assessment and best-practice research

Status: implemented
Updated: 2026-10-27

Date: 2026-10-27 · Scope: `alexandria/`, `alexandria-cloud/`, `alexandria-relay/`, `alexandria-monitoring/`, `website/`, plus the workspace root (`AGENTS.md`, `CLAUDE.md`, `docs/`). Read-only assessment. Implemented on 2026-10-27, with one change from §3.4: finished plans were deleted rather than archived (see [`../README.md`](../README.md#removed-docs)).

## Executive summary

1. **Volume is the main problem, and most of it is in one repo.** There are 113 Markdown docs and about 28k lines (excluding `.venv`). `alexandria/docs/` alone has 58 files, about 18.4k lines and 1.4 MB. Three plan/work-log files make up about 450 KB, roughly a third of it: `assessment-remediation-plan.md` (207 KB), `rebuild-execution-plan.md` (163 KB) and `instructor-studio-mcp-plan.md` (82 KB).
2. **The READMEs are 3–10× longer than benchmark projects.** They run 196–793 lines. Tauri, Vite, Vue, Deno and rust-lang/rust use 60–116 lines and send everything else to a docs site, `CONTRIBUTING`, or guide files.
3. **"How do I run it" is buried.** It starts at line 211 of 629 (app), 653 of 793 (Cloud) and 416 of 438 (website).
4. **No repo has a docs index.** The app README links 15 of 58 docs, and nothing marks which docs are live and which are history.
5. **Completed and retired plans sit next to live references, unlabelled.** About 26 of 43 top-level app docs have no `Status:` or `Triage:` line, and the ones that do use three different formats.
6. **There are 21 concrete contradictions or stale references** (§1.6). Examples:
   - The README says the security remediation is unfinished; the audits say it is remediated.
   - The README says DAO priors "shipped"; the priors doc says they were retired.
   - The README states the wrong DHT namespace key.
   - The root `AGENTS.md` lists a sub-project that doesn't exist, the wrong iroh version and MSRV, and "90 migrations" (there are 27).
   - Six links in `release-pipelines.md` are absolute home-directory paths, broken for everyone else.
7. **The same rules are copied 6–8 times.** The commit convention, the doc-review rule and the code-style rule each appear in up to 8 files, and the copies have started to diverge.
8. **The agent files describe file layout and line counts.** Anthropic's guidance says not to, and the counts are already wrong (three files give three different counts for `types/index.ts`). The root `AGENTS.md`, `CLAUDE.md` and `docs/` are also **not in any git repo**.
9. **Top recommendations:**
   - (a) Cut each README to a ≤150-line skeleton and move its sections into named docs.
   - (b) Add a `docs/README.md` index per repo.
   - (c) Archive or delete completed plans, with a uniform `Status:` header.
   - (d) Fix the 21 contradictions.
   - (e) Make `AGENTS.md` canonical, have `CLAUDE.md` import it, and keep both under 200 lines with no code maps.
   - (f) Add CI for links, absolute paths, README size and status headers.

## Method and caveats

| Item | Note |
|---|---|
| Inventory | `find` over each repo, skipping `node_modules`, `target`, `vendor`, `patches`, `.git`, `worktrees`, `output`, `work`, `dist`, `.nuxt`, `.output` and `.venv`. Line and KB counts come from `wc`. "Last commit" comes from `git log -1 --format=%cs -- <file>`. |
| Branches | `alexandria` is on `feat/skill-graph-atlas-integration`, which is `main` plus 3 doc-only commits (the skill-graph spec, tickets and research). The local `alexandria-cloud` checkout is on `feat/push-notifications`, 12 commits behind `main`, so the **Cloud inventory was taken from `main` via `git ls-tree`/`git show`**. The other repos are on `main`. |
| Root | `alexandria-mark3/` is not a git repo. The root `AGENTS.md`, `CLAUDE.md` and `docs/` have no commit history; dates shown are file mtimes. |
| Link check | A relative-link existence check across all docs found only 1 broken target (`plugins.md → screenshots/x.svg`, which looks like an example path). It does **not** catch absolute home-directory links, which resolve locally but break on GitHub (§1.6 #15). |
| Classification | Audience and type come from each doc's title, header and opening paragraph, plus spot reads. Types use Diátaxis (tutorial, how-to, reference, explanation) or plan/spec/audit/research/runbook/worklog. |
| External research | Primary sources only, all fetched 2026-10-27, with URLs in Part 2. Three Anthropic/OpenAI URLs redirected to new hosts and were followed. |

### 2.3 Principles

| # | Principle | Evidence |
|---|---|---|
| P1 | A README is an entry point (what, why, quick start, where to go next, help, license), not the documentation itself. | GitHub About READMEs; Google READMEs; Write the Docs |
| P2 | Long content goes into named sibling docs or a docs folder or site, linked from a short "quick links" block. | ripgrep; Vite `docs/`; rust-lang/rust → dev guide; Tauri ARCHITECTURE.md |
| P3 | Keep the four doc types apart. Don't mix tutorial, reference and explanation in one page. | Diátaxis start-here |
| P4 | Restructure in small steps; don't scaffold empty trees. | Diátaxis how-to-use |
| P5 | Completed specs are frozen history. Changes become new documents, and status is a header field. | Rust RFCs; PEP 1; Nygard |
| P6 | Status is machine-readable metadata from a fixed set, with `replaces`/`superseded-by` links. | KEP `kep.yaml`; PEP 1 headers |
| P7 | Progress goes in a tracker, not the design doc. | Rust RFCs (tracking issues) |
| P8 | Decisions are short (one or two pages), numbered and never renumbered. | Nygard; adr.github.io |
| P9 | Delete dead docs; update docs in the same change as the code. | Google best practices |
| P10 | Agent files stay short (under 200 lines, ≤32 KiB combined), hold only what the code can't tell the agent, and leave out layout tours. | Claude Code memory and best practices; Codex AGENTS.md |
| P11 | In a monorepo, each package gets its own README and nearest agent file; the closest file wins. | Google READMEs; agents.md; Claude Code memory |
| P12 | Treat docs as code: lint, link-check and run presubmit checks in CI. | Write the Docs; KEPs; markdownlint, lychee, Vale |

### 3.5 Proposed `docs/` layout and status convention

Phase 1 (minimal churn; matches Diátaxis' "no empty structures"):

```
alexandria/docs/
  README.md        ← index: Use · Run · Build · Understand · Specs (open) · Audits · Archive
  <feature>-spec.md + <feature>/NN-*.md   ← unchanged (tracker convention and its grep rely on this)
  <live reference / explanation / runbook docs>   ← unchanged paths, now with Status lines
  adr/             ← NNNN-title.md, ≤2 pages (already expected by docs/agents/domain.md)
  audits/          ← security and performance audits, monorepo index
  demo/            ← setup, runbook, presenter notes
  archive/         ← completed/superseded plans + README.md listing them (and tombstones if deleting)
```

Phase 2 is optional, once Phase 1 has settled. Group the remaining live docs into `guides/`, `reference/`, `explanation/` and `runbooks/`. Moving them also requires updating `issue-tracker.md`'s list command. Today it is `grep -l '^Triage:' */docs/*.md */docs/*/*.md`, which already matches one level of subfolders.

Status header for every doc in `docs/`. It extends the existing `Triage:` block, with one format and fixed values in the style of KEP and PEP:

```
Status: draft | active | live | implemented | superseded | retired | archived
Updated: YYYY-MM-DD
Superseded-by: <path>          (when superseded/retired)
Triage: …  Repos: …  Part of: …   (specs only, unchanged)
```

Rules:
- `implemented` and `archived` docs are frozen (P5). New work starts a new spec.
- Progress lives in commits and `## Notes`, not in the body (P7).
- Absorb the three current formats (`Status:`, `**Status:**`, `> **Status:**`).

### 3.6 Rules to prevent re-bloat

| Rule | Mechanism | Source |
|---|---|---|
| README ≤ 200 lines (warn at 150) | A CI step: `wc -l README.md` | §2.2 benchmarks; P1 |
| Every `docs/**/*.md` except indexes has a `Status:` line from the allowed set | A grep in CI | P6; KEP presubmit |
| No absolute paths or local artifacts (home-directory paths, `worktrees/`, `.git/`) in committed docs | A grep in CI | §1.6 #15, #17 |
| Relative links resolve | `lychee --offline` (or the script used for this report) in CI | P12 |
| Markdown lint (headings, no hard-wrapped 3,000-character lines) | markdownlint-cli2 | P12 |
| Agent files ≤ 200 lines each, no line-count tables, no `Generated:` stamps | A CI line-count check plus review | P10 |
| Doc changes ride with code changes; closing a spec means setting `Status:` and moving it to `archive/` | Add to `docs/agents/issue-tracker.md` and CONTRIBUTING | P5, P9 |
| Specs ≤ ~2 pages plus tickets; plans don't become work logs | Review convention; size warning at 50 KB | P7, P8 |
| Quarterly 30-minute "bonsai" pass: run the inventory script, archive anything `implemented` for over 30 days | A calendar or scheduled agent | Google ("frequently trimmed"); Claude memory ("review periodically") |
