- Statement: [docs/learning-standards-conformance.md](../learning-standards-conformance.md), linked from the spec's "What conformance means here" (one added line). Every number in it was read from the matrices, the pinned failure file and the tickets' Notes, and checked against the code after both review fix-ups were merged.
- Wording decisions:
  - SCORM 1.2: "conformant, self-tested", with six known deviations, all lenient validation (valid content is never refused).
  - SCORM 2004: "partially conformant, self-tested" as a whole. By area: content aggregation conformant; run-time environment conformant with known deviations (the suite's `DMI` case fails only on lenient validation and three error codes); sequencing and navigation partially conformant, because 45 of the 184 sequencing cases fail in the vendored engine. The 47 failing cases are listed by cause. The sequencing wording changes only when those cases pass.
  - cmi5: "cmi5 packaged assignable units, self-tested", the matrix's own wording, never "conformant LMS".
  - App statements: "well-formed for xAPI 1.0.3 and 2.0", backed by the canonical tests, the store agreement test and the four external stores.
  - Record store: "conformant, self-tested with the official xAPI conformance suite", explicitly without a certificate until the hosted run.
- Device runs, the repeated identifier check with real records, the hosted run, CATAPULT's manual procedure and the Windows and Linux runs are listed as not yet run; ticket 28 records their results in the statement.
- Cloud gaps are described from the cloud integration branch as it stands and the tickets' Notes. A cloud review fix-up (narrowing, `/xapi/` rate limiting, forwarding) may change some of them; reconcile the record store section when it lands.
- Deviation: the statement lives in the app repository only. The hosted service gets a pointer (edit 19), not a copy, so there is one place to update.
